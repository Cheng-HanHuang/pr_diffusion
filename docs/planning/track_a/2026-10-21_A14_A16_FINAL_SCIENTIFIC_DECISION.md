## 2. Quantitative ruling
**True head-to-head phase retrieval comparator: FAST-DIPS.** On the eight exposed B22 image/observation pairs, common saved RGB8 *raw-orientation GT best-of-K* K4:
- native FAST-DIPS **31.525134 dB**, native DAPS **31.517951**, NP LF **30.388019**, NP S2 **30.221876**, SITCOM **27.438794**. FAST K4 ~14.851 sampling-only seconds/image, or **~32.440 s/image summing four full programs after imports**; native NP LF K4 historical A1.2 ~147.40 **whole subprocess wall** seconds/image. Scopes differ, so **do not divide these into an exact speedup ratio**. Nevertheless FAST's measured quality and low observed cost make the original NP intermediate DAPS/SITCOM 'Pareto' argument unconvincing without an independent advantage over FAST. With Good25 8/8 for all K4, that success rate does not separate methods here.
- A1.6 on **its own paired seeds**: `lf_native` 30.2307 dB, `lf_fast_post` **30.4151**: **+0.1844 dB** on an eight-image GT K4 oracle, with +1.206 dB from ID67174 alone and only +0.038 dB among other seven. Root mean ~+0.032 dB, Bad20 **9/32 unchanged**. Both ~123.84 adjusted vs123.30 subprocess seconds per K4 image; avoid claiming runtime improvement from unadjusted 127.29s native, which includes 27.645s extra one-off smoke verifier divided over eight.
- A1.6 sparse two-branch+FAST vs native LF K4 **30.2209 vs30.2307** (-0.0099 dB) with **4392 vs8800 UNet forwards per K4 image (~50% reduction)** and whole subprocess **71.51 vs123.84 seconds/image (~42.3% reduction)**; however single-root mean **−0.697 dB** and same Bad20 9/32; arm changes proposal count, persistent branching and correction at once. No sparse-only/no-branch/no-correction factorial or isolated multi-basin causal evidence. FAST remains a substantially better quality/compute control.
- A1.6 150-step NP+FAST **27.0045dB oracle K4** and **16/32 Bad20** vs native NP LF 30.2307/9/32, so no evidence that simply matching FAST's nominal step count preserves NP quality.

**Scientific judgment:** A1.4 already found no publishable case for NP as a generic DAPS–SITCOM compromise. The paired source-verified FAST control and A1.6 negative/weak gains **strengthen the STOP**. Neither 260 successful roots nor a favorable exposed best-of-K result can substitute for a novel improvement relative to a strong modern baseline. Do **not** spend another multi-hour GPU night expanding NP hyperparameter variants under the same architecture. This is a decision about the currently studied **standalone method paper**, not a claim that all possible NP ideas are impossible.

## 3. Secondary findings worth preserving, but not claimed as a new method
1. **GT-free final-score sensitivity:** native FAST K4 signed-y terminal residual selector: **31.483358dB** vs its GT-oracle **31.525134dB**, Good25 8/8, regret 0.041776dB. A1.6 within NP LF+FAST-post: signed selector **30.387dB**, GT oracle 30.415, clipped selector **23.619dB**, Good25 8/8 vs5/8; within sparse beam2 signed30.153 vs clipped22.952. These are all `n=8` already-GT-exposed exploratory results from post-generated candidate sets, not a prevalidated portable rule. Signed vs clipped preference **reverses for DAPS** on A1.3; a single pooled measurement-residual selector over all 16 candidates in A1.3 favored SITCOM all 8/8 despite inferior GT raw-PSNR. Hence **NO** universal signed-likelihood selector, across-method method router, or guaranteed rotation/orientation identifier follows. Reuse requires a **predeclared fixed policy** and independent untouched images, plus trustworthy original native GT-free policies as comparators.
2. **Simple exact signed-vs-clipped identity**, for componentwise nonnegative `A(x)`, observed signed noisy `y`, and `y_+=max(y,0)`:
   `||A(x)-y||² - ||A(x)-y_+||² = sum_{y_i<0}(2 A_i(x)|y_i|+ y_i²)`.
   This difference is candidate-dependent and can reverse restart rankings; it is a useful correctness explanation, **not by itself a new theoretical research contribution**. Retain original signed measurement in future analyses even if a sampler uses clipped target. The physics `A(x)=|F(x)|` is nonnegative; raw Gaussian observations may be negative after noise.
3. **FAST's nominal hard-ball caveat** on these archived noisy observations: mathematically `||A(x)-y||_2>=||y_-||_2`; for eight images lower bound 18.566–19.569 exceeds FAST `epsilon=.05`. Thus literal global *image-space* feasible ball is empty for **these archived observations**. But native FAST's hard constraint is enforced on auxiliary variable inside finite ADMM and final image need not satisfy hard ball. This observation is **not a proof the FAST algorithm is invalid or a bug**. No claim that a trivial first zero-gradient iteration or final x0hat return is a new method without causal source-equivalence ablation.
4. **Orientation ambiguity** is mathematically inherent under Fourier magnitude and impacts raw-oriented PSNR; rotation-aware metric is diagnostic only. Absence of a magnitude-only orientation discriminator is **not a sampler-specific failure**, and existing DiffFPR addresses equivariant solution ambiguities. The static `A1.3` taxonomy is heuristic, not posterior mode certification.

## 4. Explicit decision among handed-off options
- **(A) STOP CURRENT NP STANDALONE METHOD PAPER: YES.** No title, abstract, venue strategy, further ablation allocation or paper-quality superiority statement based on these exposed results. Archive all A0/A1–A16 experiments; keep reports and exact PAC artifact paths. Results can later support a clearly labeled negative/reproducibility benchmark or related work in a genuinely new method.
- **(B) Independent signed-vs-clipped GT-free selection validation: NOT YET AUTHORIZED.** Physics score `||A(x)-y||` is standard Gaussian likelihood, so a positive replication of signed selection **alone** would not create method novelty. The original Xue et al. `Fourier Phase Retrieval With Diffusion Priors Guided by Failure Detection` ISCAS2025 DOI `10.1109/ISCAS56072.2025.11042933` exists, but its full algorithm was still not reviewed. Before a new selection project, define a genuinely new *predeployable observable* beyond signed residual, or a clear calibration/correctness result; directly compare prior art, frozen rules, unresolved symmetry and native selectors. New independent data provenance and source-valid code are necessary. A first, **desk-only** narrowly scoped mathematical/literature kill test is possible if assigned separately; it is not a standing GPU instruction.
- **(C) Branching/correction factorial: NOT AUTHORIZED.** A1.6 compound sparse arm controls insufficient to establish benefit from branch persistence, and remains inferior to FAST. Reopen only upon a theoretically articulated and externally relevant problem where FAST's native PR quality/compute frontier does not dominate (or an unambiguous equal-budget tail win), with fixed factorial/no-branch control and root-level failures in the objective—not just GT oracle K4.
- **(D) Track B basin-correctness question: TRACK B OWNERSHIP.** Share the mechanism-level observations if useful, but do not implement basin transitions, perturbations or a cross-track global solver inside Track A. Track B maintains independent decisions and GPU priority.
- **(E) Native FAST mechanism reproduction/ablation: NOT AN NP-PAPER RESCUE.** A separately justified software/correctness note or FAST-author reproducibility discussion is possible; no new GPU work now. The `epsilon` infeasibility and algebraic first ADMM subloop need careful full-objective interpretation and publication-priority audit before attributing bugs.

**Recommended allocation:** Close/park Track A's NP method-publication branch after this verified return; **zero additional GPU resources**, **no new executor created by this decision**. If later directed to pursue a *different* paper on GT-free PR reliability, reopen as its own hypothesis with a bounded **CPU/literature-only** novelty and identifiability study, then one separately approved independent-cohort pilot if that gate passes. This avoids relabeling the same eight images as a new validation study or continually extending an empirically inferior candidate generator.
