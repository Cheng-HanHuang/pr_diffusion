# A1.4 first-party prior-art and protocol audit — 2026-10-20

**Owner:** `codex/prdiff-track-a-a14-publication-gate-20261020`. **Scope:** desk research only; no PAC/GPU, no model sampling, no new data, no B24 confirmation305 access. The A1.2/A1.3 metrics are *retrospective eight exposed B22 examples*, not comparable new evidence.

## Audit standard
Sources below are *original paper/project/repository documents*, not only news/secondary summaries. `verified` means explicitly observed in first-party full-paper text/official code; `partial` means available article/abstract or publisher, but missing experiment details; `unknown` means cannot infer absent facts. FFHQ 256 means image resolution, **not** identical individual images, tensor preprocessing, checkpoint bytes, runtime GPU or PSNR representation. Published GT best-of-K is **non-executable**.

## FAST-DIPS crucial detailed source inspection and fair computation

1. [Official `forward_operators.py`](https://github.com/ququlza/FAST-DIPS/blob/main/forward_operators.py) defines `PhaseRetrieval` with `self.pad = int((oversample/8.0)*resolution)`, physical normalization `x*.5+.5`, `F.pad`, complex FFT via `fft2c_new(..., norm='ortho')` and magnitude; code source paths `forward_operators.py`, `misc.py` and `main.py` inspected directly. `TASK_PRESETS["phase_retrieval"]` sets oversample=2.0 and sigma=.05. `Operator.measure` returns `A(x) + .05 randn` (no clipping), making native observed y signed. **At source/formula level, the A1 and FAST operators are compatible.** This is not a claim of reproducible measured-noise *tensor identity*.
2. [Paper Table 1 and App. A.6](https://arxiv.org/pdf/2603.01591) give 100 FFHQ 256 results: `DAPS=30.253/122.100s`, `SITCOM=28.512/37.425s`, `FAST=29.253/10.354s` at **best of 4**. App A.6: time is `(sum_{i=1}^4 tau_i)/4` for phase retrieval, batch=1, pure sampling only; **correct total sampling cost** of four physical trajectories is **4× each displayed time**, namely DAPS **488.400s**, SITCOM **149.700s**, FAST **41.416s** (aggregate per image). This does **not** mean FAST is 4× faster than its stated ratio: when all methods' K=4 costs are multiplied, their ratios stay the same.
3. [Paper Fig3 and App A.7](https://arxiv.org/pdf/2603.01591) vary number of solver steps and plot mean PSNR vs **per-run** time; these x-axes likewise must be relabeled `K×time` to become physical best-of-K portfolio costs if K4 oracle scores are plotted. This is a **reporting convention issue, not a proven error** in the paper: App A.6 does explicitly disclose per-run timing. It becomes an error only when a follow-up compares GT best4 with a single run's charged compute.
4. `FAST` gets 29.253 best4 PSNR at around 41.4 s **total sample-only** on its own GPU versus our `NP LF4` 30.388 at 147.4 s **A1.2 subprocess wall**, *different images, checkpoint not byte-certified, hardware and PSNR representation*. No cross-paper quality superiority or underperformance can be inferred, but this is sufficiently strong to require FAST as a prospective competitor.
5. The FAST paper uses FFHQ test indices **0–99**, not the same as A1's 8 exposed image IDs. Its dataset distribution is nominally FFHQ, but rescaling/cropping and PSNR per-sample floating vs A1 uniformly saved PNG8 must be established. The FAST public checkpoint download and A1 known model SHA256 have not been content-matched; a common checkpoint must be frozen prospectively or exact model difference disclosed.
6. `main.py` gathers `full_samples` over `num_runs`, then calls `Evaluator.report(images,y,full_samples)`, explicitly using **GT** to compute per-run PSNR and oracle max. This is valid *offline best-K evaluation* and does not implement a deployable GT-free choice across roots. `data.py` applies `ToTensor/Resize(256)/CenterCrop(256)`. `configs_fast_dips_cli.txt` PR commands use `num_runs=4,batch_size=1,T=150,K=2,S=5,rho=200,epsilon=.05`. Data/measurement source adapters would be needed to consume a common externally provided signed observation rather than generating fresh independent noise per solver.

## Sources still unavailable / scientific STOP points
- Xue et al. 2025 ISCAS full PDF/appendix/official code could **not** be retrieved. Only authors/title/venue/DOI and a ResearchGate paper-request page were found. Need author manuscript/legitimate access before stating an H2 novelty conclusion. Never substitute a different Xue PR paper.
- FAST checkpoint content SHA versus existing frozen FFHQ checkpoint and exact metric pipeline unknown; don't claim both match until independently verified. Future code-integration would require native output, tensors, runtime and source identity gates, not only a repo URL.
- Other 2025–2026 non-FFT or *intensity-noise* PR methods are threats to method framing but not automatically mandatory parity baselines; rank by actual measurement/source compatibility.
- No retrospective table solves **population reliability** of any proposed NP score or novelty of per-trajectory noise proposals.

**Audit result:** FAST-DIPS is a serious technically promising compatible baseline, and it weakens an NP-as-cost/quality-frontier claim. The original NP paper cannot yet be justified by comparing only DAPS and SITCOM on eight exposed images.
